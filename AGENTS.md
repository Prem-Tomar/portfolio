# Portfolio Maintenance

Read PROJECT_CONTEXT.md before making changes. It records user-confirmed facts
and editorial decisions, not a request to change every item it mentions.

- Preserve existing user changes and inspect git status before editing.
- Keep the portfolio static and compatible with the existing GitHub Pages workflow.
- Maintain an architecture-first, hands-on senior IC voice.
- Preserve current skills; prioritize Rust, C++, C, Python, Go, Java, then Node.js.
- Distinguish delivered professional experience from ongoing or planned learning.
- Never invent employment achievements, project links, benchmark results or ATS scores.
- Never add PF identifiers, salary, private account details, credentials or chat logs.
- Follow the latest user instruction on publication; a previous deployment is not
  blanket permission to publish future changes.
- Verify production builds, TypeScript, desktop/mobile wrapping and resume links.
- For resume changes, follow resume/README.md and visually check every page.
